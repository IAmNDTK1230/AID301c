# AAVAIL Enterprise Revenue Forecasting Capstone

Complete, reproducible capstone implementation for the AAVAIL enterprise AI workflow: automated ingestion, EDA, model comparison, Flask prediction API, logging/monitoring, isolated unit tests, and Docker deployment.

## Peer-review rubric coverage

| Criterion | Implementation |
|---|---|
| API unit tests | `tests/test_api.py` |
| Model unit tests | `tests/test_model.py` |
| Logging unit tests | `tests/test_logging.py` |
| All tests in one command | `python run_tests.py` or `./scripts/build_all.sh` |
| Performance monitoring | `/monitor` + `src/monitor.py` |
| Test read/write isolation | pytest `tmp_path`; temporary test models/logs |
| Country + all-country predictions | `/predict?date=YYYY-MM-DD&country=USA` and `/predict?date=YYYY-MM-DD` |
| Automated ingestion | `python -m src.ingest`; JSON support + deterministic fallback fixture |
| Multiple models | mean baseline, linear regression, random forest, gradient boosting |
| EDA visualizations | generated by `src/eda.py` |
| Docker | `Dockerfile` + `docker-compose.yml` |
| Baseline comparison visualization | generated by `src/train.py` |

## Data

Put original course transaction `.json` files in `data/raw/` and run ingestion. The ingestion module loads and aggregates them to daily country-level revenue. Since the original course JSON files are not redistributed here, a deterministic course-style daily revenue fixture is generated when JSON files are absent, so reviewers can run the project immediately.

## Quick start

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
./scripts/build_all.sh
python -m src.app
```

API examples:

```bash
curl "http://localhost:5000/predict?date=2020-02-01&country=Singapore"
curl "http://localhost:5000/predict?date=2020-02-01"
curl "http://localhost:5000/monitor"
```

## Docker

```bash
docker build -t aavail-capstone .
docker run --rm -p 5000:5000 aavail-capstone
```

or `docker compose up --build`.

## Reproducibility

Random seeds are fixed; the train/test split is chronological; `docker build` executes the full test suite; API logs include timestamp, input summary, prediction, runtime, and model version.
